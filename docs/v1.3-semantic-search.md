# Optional local semantic retrieval

Exact lexical substring search remains the default. Search now offers explicit hybrid and semantic modes after enabling a local embedding configuration. Hybrid keeps exact lexical matches ahead of additional semantic candidates. Semantic similarity is a recall aid; the original message is the evidence.

The model is optional and is not bundled, downloaded or started by Weport. No provider credential or cloud fallback is used. The embedding URL accepts only literal `127.0.0.1` or `[::1]` addresses, rejects credentials/query strings and redirects, and has bounded request/response sizes and a 30-second timeout. The local service receives scoped message text during an explicit build and query text during semantic retrieval. A loopback process is still software selected by the user; choose a trusted local service.

## Setup

The supplied `scripts/local-embedding-server.py` runs an already downloaded mean-pooled ONNX encoder on CPU. Its Python dependencies (`onnxruntime`, `tokenizers`, `numpy`) belong in a separate environment, outside Weport's application dependencies. It never downloads model files. Prepare `model_quantized.onnx` and `tokenizer.json` in a local model directory, then calculate SHA-256 over the concatenation of those two files in that order. The server refuses to start if `--revision` differs from this artifact digest.

```powershell
python -m venv <local-venv>
<local-venv>/Scripts/python.exe -m pip install onnxruntime tokenizers numpy
<local-venv>/Scripts/python.exe scripts/local-embedding-server.py --model-directory <model-directory> --revision <artifact-digest>
```

In Search, expand the optional local semantic index controls. Enable local processing, set the endpoint to `http://127.0.0.1:5083/v1/embeddings`, model to `Xenova/multilingual-e5-small`, fixed version to the artifact digest, query prefix to `query: ` and passage prefix to `passage: `. Save, establish the ordinary index, select the desired chat/date/sender range, and explicitly build that range's semantic index. The server must return the configured `model` and `revision` with its indexed embeddings. Generic OpenAI-compatible servers without revision attestation require an adapter; Weport does not silently trust mutable model tags.

For an already prepared compatible E5 encoder, the optional prefix presets expose two choices: **E5 聊天语义（query/query）** uses `query: ` on both queries and chat messages; **E5 问答检索（query/passage）** uses `query: ` on queries and `passage: ` on messages. A preset changes only the two prefix fields after an explicit click; it does not select a model, change existing saved settings automatically, or enable semantic retrieval. Save and rebuild after changing prefixes. Other model families may require different preprocessing and can retain their manual configuration.

Retrieval mode survives saved searches and URLs as `检索:hybrid` or `检索:semantic`. Turning local processing off returns the selector to lexical mode. Unavailable hybrid partitions disclose lexical fallback; semantic-only queries return an error. A model, source, generation, endpoint or preprocessing change requires a fresh partition.

## Boundaries and cost

- Partitions include the full account, source fingerprint, lexical generation, model, artifact revision, preprocessing and semantic index format. SHA-256 document signatures reject edited text even if physical file metadata did not change.
- Builds filter scope before selecting documents, forming context windows or sending text to the local encoder. Each anchor has a singleton vector plus an optional window containing at most its preceding/following same-table, same-chat messages within five minutes.
- Queries apply chat, sender, kind and date scope before scoring candidates. A context vector is eligible only when every contributing message passes scope. Narrow scopes retain singleton vectors. Filtering a global fixed top-K vector list is never used.
- Each build handles at most 10,000 messages, 20,000 windows and eight million input characters. Windows are clipped to 1,600 characters, and the tested encoder additionally truncates to 512 tokens. At most 200 anchors survive cosine ranking; hybrid keeps lexical substring verification. There is no expensive cross-encoder or generative reranker.
- Truncation and unavailable coverage are disclosed. Large accounts may require a narrower explicit build; this implementation does not claim full-account semantic coverage at millions of messages. Rebuilding the same partition with another scope replaces that partition's semantic snapshot; queries outside its indexed range report partial coverage.
- Persisted vectors use checksummed atomic gzip snapshots under the managed search-index root. No model text copy is persisted in the semantic file. Every anchor and context member preserves the original DB, table, decimal string ID, ID kind and content hash. Search opens the exact anchor through the existing Reader identity path.
- Long-job state and cancellation live in the existing global search task, including window/page recreation. Source/account/config changes cancel the job before commit. Earlier committed files remain usable after a failed or canceled build.

## Actual model evaluation

`scripts/fixtures/semantic-recall.json` fixes 30 synthetic bilingual messages and 24 hand-labeled queries covering exact identifiers/URLs, Chinese and English paraphrases, cross-language questions and one split-context case. This fixture contains no private history. `node scripts/verify-v13-semantic.mjs` runs the actual SearchIndexService against the live loopback model and checks scope-first retrieval and exact source identities. The separate unit tests use artificial vectors only to test safety and persistence; they are not semantic-quality evidence.

The measured encoder was [Xenova/multilingual-e5-small](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726dd34fb83930e26aab4e9ac3899aa1fa78), upstream revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`, using the [E5 query/passage prefixes](https://huggingface.co/intfloat/multilingual-e5-small). The quantized ONNX file is 118,308,185 bytes. The combined local artifact digest is `e3b222633d142ec3041c486c4537b027807035608f159d8fd99d4a858a2e51e7`. It ran with ONNX Runtime CPU, two inference threads, on a Windows Intel Core Ultra 5 338H machine with 12 logical CPUs and 32 GiB RAM.

Initial run: lexical recall@5 was 6/24 (25%); semantic and hybrid recall@5 were 16/24 (66.7%). Hybrid recall@1 was 12/24 (50%). Exact-match queries retained their lexical behavior. This demonstrates additional recall and also material misses. It does not establish general retrieval quality, exhaustive evidence, or native source-opening acceptance. Build and tiny-corpus warm-query timings are recorded in `.ui-probe/v13-semantic/result.json`; they must not be presented as large-account semantic latency. A sampled Python model process used approximately 449 MiB RSS after inference, in addition to Weport's index memory.

An additional run used the same pinned small encoder, unchanged 30 documents and 24 queries (fixture SHA-256 `4a71fd9d61ec198aa08696c09623ac771376e2df92902c094e203c08e71fb8a2`), changing only the passage prefix to `query: `. The [model author's FAQ](https://huggingface.co/intfloat/multilingual-e5-small#faq) documents this symmetric prefix for paraphrase retrieval, while recommending query/passage for asymmetric question-to-passage retrieval. Both are explicit experimental options, not universal model recommendations.

| Small encoder preprocessing | Hybrid recall@1 | Semantic / hybrid recall@5 | Cross-language recall@5 | Exact queries recall@5 |
|---|---:|---:|---:|---:|
| `query: ` / `passage: ` (original baseline) | 12/24 (50%) | 16/24 (66.7%) | 6/14 | 6/6 |
| `query: ` / `query: ` (additional run) | 13/24 (54.2%) | 19/24 (79.2%) | 9/14 | 6/6 |

The second receipt is `.ui-probe/v13-semantic-symmetric/result.json`; the baseline receipt remains intact. Both runs passed the fixture's scope-first and exact-source-provenance assertions. Reproduce the additional run in PowerShell with `$env:WEPORT_EMBEDDING_PASSAGE_PREFIX='query: '; $env:WEPORT_SEMANTIC_OUT='.ui-probe/v13-semantic-symmetric'; node scripts/verify-v13-semantic.mjs`. The harness also accepts explicit model, artifact revision, upstream revision, endpoint and query-prefix environment settings and records both prefixes in new receipts. Five of the 24 queries still miss the target in the top five; the single context case, tiny hand-labeled corpus and observed improvement do not establish private-history quality or justify changing an existing user's preprocessing silently.

The existing disclosed 100k/1m lexical benchmark remains the scale evidence. Broader semantic quality, varied contextual conversations and larger-model resource measurements remain useful further evaluation; semantic mode stays opt-in.
