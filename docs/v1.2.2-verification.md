## Follow-up audit

The related-path audit found and fixed five additional failure patterns:

1. `LiveTask.start()` retained an earlier run's stage and detail/cancellation handle because undefined reset fields fell back to the old state. A new run now starts with cleared metadata.
2. The initial v1.2.2 snapshot guard compared local event reception timestamps with main-process start timestamps. This was a regression in that patch: an earlier server start could make all subsequent snapshots look stale. Run ordering now compares accepted main-process timestamps, including retry and delayed-event cases.
3. Snapshot expiry discarded an already-visible task's completion after renderer suspension. Matching active runs now accept aged terminal snapshots; unrelated expired notifications remain excluded.
4. WeBot's cancellation signal did not reach its AI run, and a dispatcher resolving after cancellation could still publish a success note. Cancellation now calls the owned chat's abort method, rejects late completion, and produces neither a success note nor an error notification for a cancelled run.
5. `sample_session_history` converted failed page reads and absent count keys into empty history. Failed windows now carry their original error and incomplete-coverage warning; unknown counts are explicitly unavailable.

Five initial reproduction tests failed against the previous code. The final suite includes ten additional regression cases. Fresh packaged checks consumed a 10-minute-old index completion and an export whose main-process start preceded the first renderer event by 30 minutes, then consumed that export's aged completion. No phantom running task remained. The same private offscreen run repeated note controls, automatic labeling, date-range IPC/reset and optical clipping checks without renderer errors. Typecheck, package build and benchmark checks passed; the benchmark still has no saved comparison baseline. The Windows package was rebuilt after the audit changes.
