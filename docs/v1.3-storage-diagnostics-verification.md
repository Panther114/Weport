# V1.3 storage defaults and connection diagnostics

## Implemented boundaries

- New profiles with no explicit media location and no legacy `Documents/WeFlow` directory use `{userData}/media`. The first default choice is persisted in `storage-defaults.json`, so later appearance/disappearance of a legacy directory cannot silently switch roots.
- Existing legacy caches stay active in place. Explicit configured paths and committed verified relocation maps take precedence. Nothing is moved or deleted by default selection. The existing copy/hash/restart transaction remains the only migration mechanism.
- Image, voice, emoji, SNS, analytics and storage settings resolve the effective media location through configuration. Exports remain user selected.
- Diagnostics inspect the selected account, refusing to substitute another sole account when the selection is missing. Multiple unselected accounts do not pick the first account.
- Six connection stages expose host, native initialization, source path availability, account selection, authenticated key representation and history shard coverage. Representation is reported only after page-1 HMAC authentication; raw, decoded hex passphrase and UTF-8 passphrase remain distinct.
- Copied connection summaries contain static stage text, counts and representation enums, never raw local errors, personal paths, account identifiers or key bytes. A strict stage-ID/label/action allowlist projects only bounded numeric coverage counts and known representation enums; unexpected strings in labels/details/raw output or metadata are excluded. Old reports without stages request recollection instead of copying their detailed output.
- The full local ZIP still contains detailed local paths/account/log material; the UI identifies it as sensitive and asks users to review before sharing. It is not described as a fully anonymous support artifact.
- Generic initialization sentinels direct users to staged diagnostics and the safe copied summary. Detailed logs remain available locally.
