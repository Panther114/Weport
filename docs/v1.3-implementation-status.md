## Search measurements

The million-message generated corpus contains short bilingual messages. With a 768 MiB standalone Node heap, build took 32.94 s; cold reload/query took 1.83 s; warm Chinese p95 was 3.65 ms. Heap after build/GC was 341 MiB and RSS was 964 MiB. Broad queries still stop at their disclosed result/scan guard. These figures are observations on a shared Windows machine, not native extraction timings or a representative guarantee for every corpus.

A 384 MiB standalone worker failed during the build. Inspection of the actual packaged Electron main process reported a **4,192 MiB heap limit**, despite Chromium's `--max-old-space-size=384` switch. The app's switch was not changed on the assumption that it controlled the existing Node isolate. Postings now use typed buffers instead of retained JavaScript number arrays, and build lookup maps are released before serialization. Cold-load measurements also release the preceding service to avoid keeping two corpora in one process.

## Independent boundary review

A final read-only review found three actionable defects, subsequently repaired with regression coverage:

- Restricted session listings included an unrestricted latest-message summary and sender/time fields. HTTP and MCP now return selected-chat identity/display metadata only.
- MCP resolved authentication twice and could interpret a disappearing grant as an administrator. Authentication now resolves one explicit principal; a missing grant never creates an unrestricted transport. A real initialization request tests the former race.
- Fractional millisecond lower bounds rounded downward in retrieval and scoped AI reads. Lower bounds round upward, scoped AI search retains the original milliseconds, and outbound search/read boundaries defensively exclude unauthorized dates/chats. Tests cover an interval beginning one millisecond after a message.
