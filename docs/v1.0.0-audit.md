what was fixed, and — importantly — what was **not** checked. It is not a claim of a clean sweep.

## Fixed in this sweep

**`dbPathService.autoDetect()` reported a permissions problem as "not found".**
When every candidate directory failed validation it returned one generic message. But on
macOS 14+ there is a completely different cause with the same symptom: the directory exists and
the process simply cannot read it (no Full Disk Access). The user's natural response — re-check
the path — is the wrong action, and nothing in the message hinted otherwise.
`findUnreadableCandidate()` now distinguishes `EPERM`/`EACCES` and names the fix.

## Known-failing tooling (not shipped, but recorded so it is not mistaken for new breakage)

**`WEPORT_V09_DUMP=1` (the v0.9 QA dump) fails at its group-analytics step** with
`groups: null` — the group list never populates after the analytics-hub navigation, so the run
exits 1 before reaching the layout probe that follows it. This is **not** part of `npm test` or
CI (CI runs `capture-ui.ps1`, the screenshot harness, which passes); it was found while adding
responsive assertions. I did not chase it because the cause is upstream of anything v1.0
touched, and the responsive coverage it would have provided was instead added to the screenshot
harness where CI actually runs it.

Not yet bisected to a specific commit — worth doing before relying on that mode again.

## Deliberately NOT done

- **`key_info.db` as a "current account" oracle.** Identified as more reliable than the current
  heuristic, but changing account selection without a real multi-account machine to test on is a
  risk with no verification path. Recorded in the unverified list instead.
- **Windows relocation pointer** (`%APPDATA%\Tencent\xwechat\config\<hex>.ini`, which can contain
  the literal token `MyDocument:` instead of a path). Only one uncorroborated source describes
  it; guessing at its semantics could break working installs. Noted, not implemented.
- **`radium\users\<hash>` layout** — single uncorroborated internal note. Noted, not implemented.
- **HTML export calendar navigation** (mentioned in closed issue #9). It was closed without that
  specific claim being retested, and retesting it requires a real export to open. Listed as
  unverified.
- **Style/quality rewrites** of `chatService.ts`, `ExportContext.ts`, `wcdbCore.ts`.

## Why this is bounded rather than exhaustive

`chatService.ts` (507 KB), `ExportContext.ts` (324 KB), `appMain.ts` (256 KB) and `wcdbCore.ts`
(224 KB) cannot be exhaustively audited in a finite pass with any confidence. Rather than
produce a large, plausible-looking list of speculative findings, this sweep targeted the
categories that have actually produced shipped bugs in this repository's history —
platform gates, swallowed errors on the connect path, and explicit markers — and reports the
rest as unverified.
