# v0.9.6 export IPC integration note

The renderer now uses the second argument to `electronAPI.export.exportSessions(outputRoot, options)` for scope: selected mode sends `sessionIds: string[]`; default all mode sends `sessionIds: undefined`. The main-process IPC handler must:

1. Treat an explicitly present `options.sessionIds` array as the requested scope: trim strings, de-duplicate, and intersect with the sessions returned by `chatService.getSessions()`.
2. Preserve legacy behavior when `sessionIds` is absent or `undefined` (export all eligible sessions). The renderer never sends an empty array: selected mode blocks a zero-selection run, while all mode sends `undefined`; if an empty array is received, reject it as invalid selected-mode input rather than silently treating it as “all.”
3. Apply the existing no-message filtering and export task/progress handling to the scoped list, then pass that list to `exportService.exportSessions(...)`.

Type updates for the integrator:

- In `src/vite-env.d.ts`, replace the export API’s `options?: any` with a renderer-side `ExportRequest` type containing the existing export options plus `sessionIds?: string[]`.
- In `electron/preload.ts`, keep the same IPC channel and argument order, but type the exposed `exportSessions` options as that request shape.
- In `electron/appMain.ts`, type/normalize the incoming request and implement the scope handling above; no `exportSelectionMode` IPC field is needed because all mode maps to `undefined`; no WCDB host, transport, or worker-thread changes are required.
