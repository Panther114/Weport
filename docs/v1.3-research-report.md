# Weport V1.3: research and recommended direction

Research date: 20 October 2026. Baseline: local Weport 1.2.2, commit `313c7a11dbf48cc9a53deadd22fa734d23ac047f`.

**Recommendation: make V1.3 the release for dependable personal archives and verifiable AI recall.** Prioritize export completion, archive independence, indexed search, and answers that open their original messages. Keep no-login connection as a separately gated experiment.

This research screened 14 external projects/repositories, cloned 12, and inspected implementation code in seven. It also examined Weport's implementation, acceptance records, current roadmap, and recent open issues. [The evidence appendix](v1.3-research-evidence.md) records exact source paths, inspected commits, limitations, and adoption decisions. Competitor applications were not installed or benchmarked; source inspection does not establish their runtime quality.

## Recommended priorities

### 1. Reliable exports and a durable archive library — core commitment

**User outcome:** “My export finishes, tells me exactly what is missing, and remains usable after WeChat changes.”

Extend the current orchestrator, atomic writes, recovery ledger, and integrity checker. They already provide substantial correctness machinery; do not replace them with a second export engine.

- Add task-level preflight for connection capabilities, destination access/free space, source coverage, and selected media options. State estimates as estimates; completeness requires verified collection.
- Record stage, last successful cursor/page, last progress time, and a bounded diagnostic reason for waiting. Distinguish slow work, waiting, failed work, and cancellation. A watchdog should diagnose before offering a safe retry.
- Add explicit media outcomes: original, thumbnail fallback, missing locally, decryption failure, and unsupported. Offer original-only and best-available policies. Never imply a thumbnail is an original or promise recovery of an absent original.
- Build a versioned, account-scoped archive manifest over existing loss-preserving JSON/media output. Open it through an archive reader adapter without requiring a live WeChat connection. Import Weport archives first; support validated ChatLab files later.
- Add opt-in scheduled archive jobs, retention, and a restore/open test. Include bookmarks and evidence references in the portable representation.

**Why first:** current [Weport #46](https://github.com/Panther114/Weport/issues/46) reports a stuck export, [#40](https://github.com/Panther114/Weport/issues/40) reports thumbnail concerns, and [#33](https://github.com/Panther114/Weport/issues/33) reports repeat-export verification trouble. These are reports, not established root causes. Upstream [WeFlow #1240](https://github.com/hicccc77/WeFlow/issues/1240) separately illustrates how missing capability preflight can multiply one configuration problem into hundreds of failures.

**Acceptance:** injected hangs/crashes have clear terminal or recoverable states; resumed exports preserve exact physical source identities; archived text and available media open after restarting without WeChat. Existing export checks remain authoritative.

### 2. Fast, precise search — core commitment; semantic recall is opt-in

**User outcome:** “Find the message, even in years of history, and open the correct row immediately.”

Weport's `searchIndexService.ts` explicitly documents O(N) in-memory substring scans and defers an inverted index to V1.3. Its generation/manifest commit scheme is worth preserving.

- Introduce a derived inverted index, evaluating SQLite FTS5 against alternatives using Chinese, mixed-language, names, URLs, identifiers, and substring queries. FTS token matching must not silently remove existing substring behavior.
- Share one retrieval service across Search, WeportAI, WeBot, and relevant MCP tools. Return account/database/table/local-ID provenance and index freshness/coverage.
- Reconcile edits, deletions, and history backfills. The current index documents tail refresh and a force-rebuild requirement for some deletions; replacing the query engine alone does not solve freshness.
- Add optional local embeddings over contextual message windows. Fuse lexical and semantic candidates, retain exact-match behavior, and bound reranking cost. Partition by account, source, model, and index version.
- Apply account/chat/date restrictions during candidate retrieval, or explicitly disclose incomplete candidate coverage. Post-filtering a fixed vector shortlist can miss all relevant results.

**Acceptance:** a disclosed 100k/1m-message corpus, fixed hardware, cold/warm measurements, p95 latency and RAM/disk results, and a labeled bilingual recall set. A reasonable proposed warm lexical target is p95 under 200 ms at one million messages; this is a target, not a measured result. Every accepted hit must open its exact source row.

### 3. Evidence-linked AI and correctable memory — core commitment

**User outcome:** “Show why you think this, what period you checked, and what would change the conclusion.”

- Add structured source references to tool results and AI output: account/source/session, database/table/local ID, timestamp, and content hash. Render clickable citations into Reader; handle unavailable or changed sources explicitly.
- Display investigation coverage: requested range, inspected range, unread/failed ranges, snapshot time, and truncation. Retrieval samples cannot justify claims about all history.
- Store memory as dated claims with evidence, scope, uncertainty, corrections, and superseded status. Keep raw observations separate from relationship interpretations.
- Namespace AI memory by account/profile. Current `memoryDir()` resolves under a shared workspace root rather than incorporating account identity. This is a scope to audit and migrate carefully, not proof of an observed disclosure.
- Add small evaluation sets for factual recall, temporal comparisons, contradictory messages, deleted sources, and account switching. Evaluate correctness and groundedness before increasing context or tool budgets again.

**Reference:** ChatLab's evidence assembly and typed evidence UI are concrete implementation references; Open WebUI demonstrates citation-source plumbing. Yance's proposed evidence contract is useful design input but has no supported runtime.

**Acceptance:** every displayed citation resolves or declares why it cannot; an account switch cannot reuse another profile's memory without an explicit shared-workspace choice; unsupported claims are marked as interpretations or unknowns.

### 4. Data boundaries and storage control — core minimum

**User outcome:** “I know which account is in scope, what can leave this computer, and where local data lives.”

Add enforceable per-task/per-client chat and date scopes, separate local-only and cloud-enabled processing choices, and a preview of selected outbound context. Apply the same restrictions at the service boundary for UI agents and MCP/API clients. Existing bearer authentication is valuable but does not itself express per-client data scopes.

Expose cache/archive/model locations, disk usage, cleanup, and transactional relocation. [Weport #38](https://github.com/Panther114/Weport/issues/38) reports cache files entering iCloud Documents. A local path can still be cloud-synchronized. Treat app lock as an optional screen-access feature; do not describe it as encryption of archives or indexes.

**Acceptance:** out-of-scope reads fail server-side; relocation survives interruption; exports, indexes, memory, OCR text, and model caches follow documented retention and deletion behavior.

### 5. WeBot digests that report meaningful changes — bounded follow-up

**User outcome:** “Tell me what changed since the last successful check, with source links.”

Keep the existing scheduler and cancellation improvements. Add a persisted last-success watermark, immutable source scope, run idempotency, configurable cost limits, and quiet/no-change outcomes. Advance the watermark only after successful evidence collection and result commit. Prototype three templates: decisions and deadlines, unanswered questions, and weekly highlights. Detected commitments remain user-reviewable interpretations.

Khoj provides timezone and process-lock patterns, but its inspected notification decision uses an extra model call and falls back to notifying on parsing/error. Prefer deterministic no-change suppression before any optional model judgment.

**Acceptance:** no duplicate notes on retry, no notification when nothing relevant changes, no watermark advancement on failure, and no reading a newly selected account under an old task's scope.

### 6. No-login connection and platform expansion — independent acceptance track

Preserve the requirements already in [the V1.3 deferred-work plan](v1.3-plan.md). A detected key is insufficient: every required shard must authenticate, source DB/WAL access must stay read-only, and full export identity/media acceptance must pass. Snapshot history and live notifications need distinct capability states.

Time-box feasibility work before promising this as the headline. Do not delay archive/search/evidence improvements indefinitely for scanning. Preserve Electron, the pure-Node WeFlow host, and IPC architecture. Native-source research must not bypass the permanent host/runtime constraints.

macOS/Linux support needs real-account acquisition/export evidence on those platforms. Signing/notarization and live notification acceptance are separate from successful cross-platform packaging.

## Scope and sequencing

| Milestone | Deliverable | Exit condition |
| --- | --- | --- |
| Foundation | Export diagnostics/preflight, media quality states, account/source identity contract | Reproducible failure/cancellation recovery; no silent identity loss |
| Main V1.3 | Archive opening, indexed lexical search, clickable AI evidence, account-scoped memory and data access | Offline reopen/restore, search correctness, account isolation and citation gates pass |
| Bounded additions | Optional semantic recall; three delta-digest templates | Demonstrable retrieval benefit and controlled cost/noise |
| Separate experiment | No-login scans/mirrors; further native platform acceptance | Existing per-shard, read-only and real-account gates pass independently |

Treat full archive browsing and search as the primary flow; add AI interpretation on top of that stable evidence layer. Use the existing palette, motion/reduced-motion, body-portal, background-task, and offscreen-probe constraints for any later implementation.

**Defer:** a runtime rewrite, broad new platform connectors, always-on screen recording, 3D relationship graphs, automatic sending, expanded personality cloning, and generic agent/plugin marketplaces. ChatLab already covers much of the analytical breadth; current requests and inspected failure modes justify investing in reliability and useful recall first. Optional OCR should follow media quality/account scoping and run only on selected local assets, with derived-text provenance.

This sequencing is an engineering/product judgment, not user-demand research or a calendar estimate. No competitor runtime tests, live-account access, paid model calls, or application changes were performed for this report.
