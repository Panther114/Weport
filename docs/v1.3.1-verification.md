# Weport v1.3.1 Implementation and Acceptance

Validated on Windows x64, 7 November 2026. Work branch: `version-1.3.1`.

## Integrated changes

- Merged PR #47 (full archived-account identity validation) and PR #51 (native-platform build routing and macOS realpath acceptance).
- Separated automation indexes, transcripts, archived turns and workspace notes from interactive AI chats. Migration verifies copies, commits the destination first, retains recovery originals and recognizes legacy dispatcher prompts, including archived prompts. Removed tasks retain their history.
- Added a default-on memory choice when creating chats. Disabled chats cannot use shared-memory paths, memory tools or previous-analysis retrieval. Removed response-style/language restrictions and rewriting of saved user text.
- Added source-aware reverse quote lookup with exact decimal server IDs, ambiguity detection, pagination, account fences, background progress and Reader navigation.
- Added account-bound incoming-message regex triggers independent of notification settings, with bounded regex workers, persistent deduplication, cooldowns and queued execution.
- Made notifications use capture-compatible rendering by default; desktop capture and OS capture exclusion require explicit live-glass selection.
- Staged global analytics rendering, loaded group panels on demand, scoped caches to the account/database and propagated cursor failures. Word-frequency scanning stops fetching at its existing sample cap.
- Separated Reader preview/full-quality caching and searched for higher-tier original image files before retaining display/thumbnail cache entries.
- Added persistent account-bound Moments protection requests. After WeChat exits, the service uses the existing backup/write guard, checks the requested account again and verifies the installed state. It retries failures and detects a subsequently missing trigger.

## Acceptance evidence

- Renderer and Electron TypeScript checks passed.
- Vitest: **2,052 passed, 8 skipped**, across 162 files. Native/build script tests: **39 passed**.
- Fresh production Vite/Electron/host bundles and Windows NSIS installer built successfully. `latest.yml` contains v1.3.1 notes and the installer SHA-512.
- New packaged UI acceptance covers memory choice and status, archived WeBot history, regex task creation, pending Moments feedback, statistics rendering before a deliberately slow word scan, group heatmap loading on demand, exact-identity quote lookup/body portal/Escape, and default popup capture exclusion being off. No renderer errors.
- Synthetic encrypted databases were read by the actual packaged WCDB host. Message identities/content, close/reconnect, memory creation through real IPC and a native reverse-quote scan passed. Source and copied fixture hashes were unchanged.
- Existing packaged acceptance covered 102 responsive UI checks, Moments enable/disable/error handling, repeated routing/window recreation, CLI authentication/protocol and isolated MCP/HTTP authorization and account fences.
- The offscreen performance harness passed its functional checks with generated backdrop frames. No comparison baseline was available, so this establishes a successful sample, not a quantified performance regression verdict. No user desktop frames were captured.

Receipts and screenshots are generated under `.ui-probe/`; release binaries under `release/`. UI fixtures are synthetic. All app launches use private profiles and hidden/offscreen windows. The locally installed application is not reinstalled.

## Practical limits

- Missing local originals cannot be reconstructed; WeChat must download them first.
- The default popup was verified to have OS capture exclusion disabled. NVIDIA Instant Replay itself was not reproduced on the reporter's hardware.
- Moments protection is deferred until a safe exit of WeChat; it does not write a live WeChat database or recover posts already deleted before protection was applied.
- Progressive rendering and reduced unnecessary scans are verified. No fixed speedup is promised for every history size.
- macOS/Linux native execution and packaging require their respective runners. The release proceeds without waiting for GitHub Actions, as requested; those platform results are not claimed as locally verified.
