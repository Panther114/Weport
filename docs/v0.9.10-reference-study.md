# Weport v0.9.10 reference-study ledger

This ledger records the read-only reference work required by the v0.9.10
(WeClone 人格克隆) requirements marked `***`. Reference code and assets remain
design evidence; none are shipped or imported into the build.

## Persona generation pipeline (`***`)

- References studied: `reference-projects/WeChatMsg` export masking and
  report/persona text generation (docs-only clone); `reference-projects/EchoTrace`
  analysis-report structure; `reference-projects/WeFlow` cursor-based message
  scanning already ported into `wcdbService`.
- Adopted: staged MD persona files (profile / relationships / knowledge /
  timeline) instead of one monolithic prompt, per-file retryable LLM calls, and
  a preview-before-upload confirmation step.
- Rejected: copying WeChatMsg's PyWxDump decryption path or any client-side
  database access outside the WCDB host; generating personas in the renderer
  process.
- Weport deviation: history is read through the existing message-cursor host
  protocol (500/batch, 150k/session cap) so memory stays flat on 1M-message
  accounts; MD staging lives under `userData/weclone-staging/` and is cleaned
  after upload.

## Retrieval and persona chat (`***`)

- References studied: `reference-projects/Reasonix` cache-aware context
  maintenance (retrieval budget + stable system core); LLM auto-reply persona
  handling in `reference-projects/wechat_chatter`, `reference-projects/WeChatFerry`,
  and `reference-projects/Wechaty`; `reference-projects/CipherTalk` AI chat panel.
- Adopted: Reasonix's split of a small always-present context core (profile.md +
  relationships.md) from a bounded retrieved tail (BM25 top-K 8–12 chunks),
  plus explicit "say 记不清了 rather than invent" grounding rules.
- Rejected: hook-based bots' approach of replying inside the live WeChat client,
  and any moderation layer over profanity/slang — persona fidelity requires the
  original tone, while sensitive questions are refused server-side via a
  non-overridable system prefix.
- Weport deviation: retrieval runs on the server over sanitized chunks only;
  the client never streams raw history to chat time, and temperature is raised
  (0.9) for tone diversity instead of guardrails.

## BM25 vs vector DB (`***`)

- References studied: `wink-bm25-text-search`-style inverted-index designs and
  CipherTalk's local retrieval helpers; embedding-store approaches considered
  upstream (sqlite-vec / pgvector / transformers.js).
- Adopted: a dependency-free hand-written BM25 with the CJK bigram tokenizer +
  stopword list shared from `wordFrequency.ts`, lazily built per clone and kept
  in an LRU (≤5 indexes), with substring fallback when recall is empty.
- Rejected: vector databases — sqlite-vec/pgvector need native builds (breaks
  the zero-native-deps Docker image) and transformer embeddings add a 100 MB+
  model resident in RAM, which contradicts the <100 MB Railway budget, for
  marginal gain on short chat chunks where lexical overlap dominates.
- Weport deviation: chunking happens client-side (800 chars) so the server
  never re-tokenizes uploads; index build is deferred to first chat to keep
  cold starts instant.

## Server storage: JSON vs SQLite (`***`)

- References studied: `reference-projects/CipherTalk` better-sqlite3 usage and
  its MCP/HTTP service mode; `reference-projects/wechat-chat-exporter` MCP
  server exposure patterns.
- Adopted: single-process Fastify with static SPA hosting, Bearer owner tokens
  stored as SHA-256 hashes, and atomic tmp+rename writes for the meta file.
- Rejected: better-sqlite3 — a native module that forces node-gyp toolchains
  into the Alpine image, risks build flakiness, and buys nothing at this scale:
  metadata is tens of rows and blobs are append-only JSONL streamed from disk,
  never fully resident.
- Weport deviation: the design doc originally proposed SQLite meta.db; the
  implementation ships pure JSON (`meta.json`) + filesystem blobs, which also
  makes delete-and-purge trivially verifiable (`rm -rf blobs/<id>` + meta row
  removal, fsync before response).

## Low-RAM proxy vs local LLM (`***`)

- References studied: CipherTalk's local speech/LLM integrations (sherpa-onnx)
  and WeChatFerry's in-process DeepSeek/Gemini clients.
- Adopted: the server is a thin streaming proxy to an OpenAI-compat upstream
  (`WECLONE_LLM_BASE_URL`), with SSE pass-through and mock mode when no key is
  configured; heavy generation stays on the user's own provider via
  `weportAiService` during MD creation.
- Rejected: running a local model on Railway — free/entry tiers cap RAM far
  below any usable LLM, and GPU instances defeat the "one-click, near-free"
  deployment goal.
- Weport deviation: only the WeClone API is exposed publicly; httpService
  (5031) and mcpService (5032) remain bound to 127.0.0.1 and are not packaged
  into `weclone-server`.

## PII filtering: regex + LLM double pass (`***`)

- References studied: WeChatMsg's nickname/address replacement options,
  chatlog-export's dedupe/anonymization passes, EchoTrace's privacy notes.
- Adopted: deterministic regex rules (身份证/手机号/Luhn-checked 银行卡/邮箱/
  住址窗口/密码密钥/车牌) executed 100% locally before anything leaves the
  device, then a sampled LLM second review (MD + ~5% messages) for contextual
  leaks such as name+address combinations, with a UI hit list and manual edit.
- Rejected: a single pass — regex alone misses contextual PII phrased in
  natural language; LLM-only review would require sending unsanitized text
  off-device first and costs prohibitive tokens on full corpora.
- Weport deviation: the server re-runs the same regex table as a third guard
  against bypassed clients (reject above `WECLONE_PII_MAX_HITS`, sanitize below
  it), and `src/utils/pii.ts` must stay rule-for-rule identical to
  `electron/services/weClonePiiFilter.ts`.

## Popup click-through navigation

- Reference studied: WeFlow's notification popup (already ported as
  `notificationWindow.ts`) focus/click behavior.
- Adopted: click-to-show-main-window with session deep-navigation, keeping the
  popup non-focusable and click-through while hidden.
- Rejected: making the popup itself interactive beyond click-to-open — it must
  stay a glanceable overlay.
- Weport deviation: navigation reuses the existing main-window show path
  (including the discard/reload flow) so hidden-window state is preserved.
