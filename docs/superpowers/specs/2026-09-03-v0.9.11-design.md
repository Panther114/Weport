# Weport v0.9.11 design

## Goal

v0.9.11 fixes the sole open bug issue, makes notification selection follow WeChat state, and repairs concrete macOS/Linux integration defects that can be corrected in this repository. It does not add automatic sending to personal WeChat accounts because Weport has no supported outbound transport and its core is intentionally read-only.

## Scope and decisions

### Issue #15: macOS image-key workflow

Issue [#15](https://github.com/Panther114/Weport/issues/15) reports that selecting image export on macOS does not request an image key. The issue has no body or reproduction details, but the local failure is deterministic: the renderer excludes Darwin from both the missing-key guard and key controls, while `imageDecryptService` requires XOR/AES material for `.dat` media on every platform.

The image-key controls and export guard will cover Windows, macOS, and Linux. `key:scanImageKeyFromMemory` will dispatch to `KeyService`, `KeyServiceMac`, or `KeyServiceLinux` instead of rejecting non-Windows hosts. Existing account-scoped encrypted key persistence remains unchanged. Errors will identify whether cache extraction, native helper execution, or memory scanning failed.

### WeChat mute state

`MessagePushService` will batch-refresh candidate session statuses through the existing native `wcdb_get_contact_status` abstraction before emitting chat notifications. A new default-on `messagePushRespectWechatMute` setting will suppress incoming notifications when `isMuted` is true. Suppressed messages still advance baselines and deduplication state so unmuting a chat cannot replay old messages.

Status lookup failures fail open and emit bounded diagnostics. This avoids losing all notifications when a WeChat/native schema change makes status unavailable. The setting is exposed in the notification UI and is independent of whitelist/blacklist selection.

### Mention-only notifications

The existing filter mode gains `mentions`, displayed as “仅 @我”. It applies only to incoming group messages and composes with the WeChat-mute rule: a muted group remains silent. `@所有人` does not count as a direct mention.

Mention detection uses structured message-source metadata (`source`, `msg_source`, or `message_source`) and reuses ChatService’s existing identity normalization and `<atuserlist>` parsing. Visible `@name` text is not used because it produces false positives. The message parser will retain only the source data needed for this decision; no new content leaves the local notification pipeline. If source metadata is absent, mention-only mode fails closed for that message and emits bounded diagnostics.

The main-process `messagePushFilterMode` is authoritative for chat filtering. The duplicate `notificationFilterMode` remains synchronized for compatibility with the popup layer, but mention evaluation occurs only once in `MessagePushService`.

### Notification selector ordering

The selector will retain `sortTimestamp`/`lastTimestamp` from `chat.getSessions()` and order sessions newest first, with the normalized session ID as a deterministic tie-breaker. Contact-name enrichment must not reorder the list. Existing type/search filters operate on that ordered array.

## macOS and Linux hardening

### macOS packaging and runtime

The macOS package currently contains `libwcdb_api.dylib` with an unresolved `@rpath/WCDB.framework/...` dependency. Weport will adapt WeFlow’s packaging-time approach: an `afterPack` script will inspect the copied dylib and rewrite that dependency to the colocated `@loader_path/libWCDB.dylib` using `install_name_tool`. The build fails if the expected dependency remains unresolved. This preserves the existing WCDB subprocess architecture.

`KeyServiceMac` will no longer reject solely from the `csrutil` status probe. It will attempt the existing elevated helper, then map actual attach/AMFI failures to honest SIP guidance. It will not claim that administrator authorization bypasses SIP.

The shipped arm64 WCDB/key binaries declare macOS 15 as their minimum, while `image_scan_helper` declares macOS 26. Their source/toolchain is not present, so v0.9.11 cannot responsibly rebuild them. The app and documentation will declare macOS 15+ for the core app, preflight incompatible helpers, and avoid launching `image_scan_helper` below its deployment target while preserving cache-based extraction and the alternative scanner when available. Intel remains unsupported.

Developer-ID signing and notarization require external Apple credentials and are outside this local implementation. Unsigned/ad-hoc builds will describe manual update and login-item limitations rather than promise unsupported behavior.

### Linux discovery, process handling, and diagnostics

Database discovery adds common native, XDG, and Flatpak locations, including `~/.xwechat/xwechat_files`, `~/.local/share/xwechat_files`, and `~/.var/app/com.tencent.WeChat/data/xwechat_files`.

Key capture will discover exact supported process names (`wechat`, `wechat-bin`, `wechat-uos`, `weixin`, and `xwechat`) without shell regex interpolation. It will attach to an existing process when possible. If launch is required, it will start one resolved executable and stop after success; it will not kill every WeChat process or spawn all candidates concurrently.

Preflight diagnostics will identify missing executable permission, `libcrypto.so.3`, `libcurl.so.4`, glibc/libstdc++ incompatibility, and restrictive Yama `ptrace_scope`. The documented binary floor is glibc 2.34, GLIBCXX 3.4.30, and OpenSSL 3 unless native artifacts are later rebuilt against an older baseline. AppImage FUSE fallback instructions will be documented.

Linux autostart will use an XDG `.desktop` entry under `${XDG_CONFIG_HOME:-~/.config}/autostart` with an escaped executable path and `--background`. Enable, disable, and status checks use the same file. Linux update UI will use manual GitHub-release download because Electron `autoUpdater` does not support Linux.

### Deferred platform items

Bundling FFmpeg and replacing transparent desktop-capture notifications with native system notifications are valid follow-ups, but both materially change distribution licensing or product presentation. v0.9.11 will add precise diagnostics/fallback messaging where feasible and record these as unresolved rather than silently expanding scope.

## Automatic reply feasibility

No automatic reply sender will ship in v0.9.11. WCDB is not a send API, and direct database insertion is rejected. The studied working implementations rely on version-specific process injection, accessibility automation, or external bot/provider accounts; none supplies a reliable, cross-platform personal-account transport compatible with Weport’s safety and read-only expectations.

A future design may add a provider boundary with no default provider, explicit per-chat allowlists, preview/manual confirmation by default, quiet hours, cooldown and daily rate limits, idempotency, self-message/loop guards, encrypted credentials, local audit logs, and a global kill switch. That design is intentionally not scaffolded until a supported outbound provider exists.

## Testing and acceptance

- Add unit coverage for filter composition, structured mention detection, mute suppression/baseline advancement, recency ordering, platform path discovery, and Linux process selection where functions can be isolated.
- Extend deterministic screenshot/demo handlers for the new notification settings without persisting data.
- Run `npm run typecheck`, focused tests, the normal build chain, and the Windows visual smoke harness.
- Add static package checks for the macOS install-name rewrite and Linux helper mode/dependency diagnostics.
- Hardware acceptance remains required for macOS 15+ Apple Silicon with WeChat 4.x and Linux x64 on Ubuntu 22.04/24.04 or Debian 12 under X11/Wayland. Results not executable on this Windows host must be reported as unverified.

## Reference study and attribution

The following repositories are design evidence only; no source or binary is copied blindly:

- `reference-projects/WeFlow`: adopt its macOS `install_name_tool` packaging pattern and structured mute/notification behavior; retain Weport’s WCDB host subprocess and slim popup. WeFlow-derived code remains attributed under the existing project notices.
- `reference-projects/wxchat-export`: adopt path/process discovery and capability-oriented SIP/Yama diagnostics; reject automatic privilege/security-policy changes.
- `reference-projects/wechat_chatter`: study macOS Frida/OneBot reply flow; reject version-specific injection and offsets.
- `reference-projects/WeChatFerry`: study the Windows outbound hook boundary and contact mute schema evidence; reject a Windows-only injected sender.
- `reference-projects/Wechaty`: study provider/puppet isolation; reject external-login/provider dependence as a built-in personal-account sender.
- `reference-projects/chatlog-export`: use contact schema evidence for mute fields; continue consuming the existing native abstraction rather than coupling to a single schema version.

Authoritative platform references include Apple’s SIP/runtime protection and debugger-entitlement documentation, Electron’s app/login-item, updater, and signing documentation, Linux kernel Yama documentation, and AppImage FUSE troubleshooting guidance. Links will be recorded in the platform troubleshooting/reference notes.
