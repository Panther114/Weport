# V1.2 implementation and acceptance

## Architecture

- Windows x64 native packaging must pass `scripts/verify-native-assets.cjs` and the copied-asset check in `after-pack.cjs`. Offline repair only accepts the exact original binary hash; never modify native binaries at runtime or extend the expiry to a later date.
- KeyHealth and Diagnostics quick/full checks use `verifyHexKeyForPage` for identical raw/decoded-passphrase/UTF-8 contracts. Mirror material may use an account passphrase only after authenticating each current database page.

- Electron is the desktop runtime. The Tauri prototype is retired. Do not add a second IPC bridge or engine.
- Keep the existing pure-Node `WeFlow.exe` WCDB subprocess and Node IPC transport.
- Native `execQuery` does not bind its optional parameter array. Exact lookup uses validated quoted ID tokens, preserves uint64/signed-int64 equivalence, and rejects ambiguous matches; never reintroduce `?` placeholders without implementing native bindings.
- Build with `vite --config vite.config.mts`. A stale generated `.mjs` shadows the maintained config. Vite 8 Electron builds use `rolldownOptions`; verify the host stays a single file and Flash entries exist.
- Windows scanned keys are raw page keys, not account passwords. Connect by validating and rekeying a disposable mirror; never write the source database during scan or conversion.
- Validate raw bytes, UTF-8 hex text, and decoded-hex-byte passphrase modes separately with page-1 HMAC. For the Oct 3 Windows control, only decoded-hex-byte passphrase mode matched. Never infer mode from 64-hex shape.
- A scan is connection-ready only when the session database and every message/biz-message shard have verified keys. Media readiness is reported separately.
- Scanned connections are read-only. Changes to a temporary mirror must never be reported as changes to WeChat.
- A scanned connection is a history snapshot. Refresh it when the original DB/WAL fingerprint changes before reading/exporting; reject changing sources during conversion. Live notifications require the original-key connection, not a snapshot monitor.

## User expectations

- Reader and export share account-scoped session favorites; message bookmarks are separate. Export defaults to selected-only, and account-guarded annotation requests cannot write a queued star into another account.
- Text-fast export must preserve voice XML and `packed_info_data` transcripts (protobuf field 5, completed status 2). Parse strictly; keep DB/table provenance in transcript identity. Existing text requires no WAV decoding or ASR model. Voice caches are account-scoped and shared with Search.
- Source recovery fingerprints track DB/WAL metadata, never SQLite `-shm` reader bookkeeping. Matching count/latest-time hints cannot replace a verified source/options/artifact ledger.
- Repeated server IDs do not prove export duplication: real source tables contain distinct local rows with conflicting payloads. Preserve those rows, expose source ID collisions separately, and treat repeated full DB/table/local identity or artifact mismatches as export defects. Never deduplicate by server ID alone.
- Integrity attribution must recognize native 拍一拍 type `266287972401` as a system message, consistent with the exporter. Missing system-sender names are informational; unresolved ordinary senders still fail validation.
- Automatic anti-revoke checks carry an account/opt-in lease; queued writes recheck it before native dispatch and serialize with close/reconnect. An already-dispatched write finishes on its original handle.
- Incremental export skipping requires a matching source fingerprint, options and artifact hash; count/latest-time equality is insufficient. Per-session completion and 100% are not task completion while verification remains active.

- Navigation has one compact layout; 微信/智能 remain visible without collapse or density controls. Only the workspace scrolls; wheel input over the rail must not move any ancestor or the workspace. Keep every navigation control reachable at 600 DIP. Diagnostics and runtime self-checks live only in Settings.
- Settings feedback composes a local title/body and picker-selected images. It opens the official GitHub editor; image upload and final submission are explicit user actions. Never automatically send logs, account data or screenshots.

- Search opens the exact indexed message, including database/table identity. Ambiguous matches return an error.
- Annotations are scoped to the selected account. Legacy unscoped annotations migrate to one owner only.
- Reader media lookup is local and lazy. Missing downloads remain explicit; an unknown file must not be substituted for the requested attachment.
- Export recovery requires both an unchanged source fingerprint and identical export options, plus the output file hash. A ledger alone does not prove a current export.
- Source fingerprints use file size, modification time and change time; media exports also include attachment metadata. This detects ordinary updates/downloads, not deliberately metadata-preserving content edits.
- Compatibility policy is optional and fetched with a short timeout. An offline or malformed response on a fresh start does not block the app.
- The first guarded write/acquisition/export awaits the initial bounded compatibility-policy fetch. Snapshot restore holds a WCDB maintenance lease, requires WeChat to be stopped and prevents account switching; failed replacements retain verified pre-restore copies and report rollback failures.
- Manual database writes are serialized, require WeChat stopped and close the native connection during snapshot capture. Missing main DBs, unreadable sidecars and source changes reject capture; rollback only removes absent WAL/SHM sidecars. This contract applies to guarded interactive writes, not legacy automatic trigger maintenance.
- Index and snapshot jobs persist in `taskStatusService`; start/end events wake the renderer and active polling stops at terminal state. Keep both global task rows so page/window recreation does not hide ongoing work.
- Failed native initialization retries at most once per 30 seconds, retains its original error and runs before scan-mirror conversion. Changing resource paths resets the retry window.
- Do not prune dependency folders named `doc`: ExcelJS runtime classes live in `lib/doc`. Packaged acceptance exercises an actual XLSX write and WASM keystream initialization.
- WeportFlash is an Electron portable executable, with profile and exports beside the portable executable. It has no tray, autostart, updater or scheduler. Multiple detected accounts require an explicit selection.

## Verification rules

- Probes use private profiles and `WEPORT_PROBE_OFFSCREEN=1`. All windows must be born offscreen and never focus. Screenshot fixtures contain only fake data.
- The pinned V1.1 benchmark must establish the same offscreen controls before creating a window. Never rely on moving a visible window afterward.
- Compare background RAM, background and notification CPU, actual installer bytes, and sampled peaks/growth. Record the application state and sampling interval.
- Synthetic notification frames verify renderer/compositor/IPC work. They do not measure live desktop capture or prove glass appearance over the user's desktop.
- A short stress run cannot establish day-long stability. Report that limit explicitly.
- Default installation acceptance requires a fresh package whose typecheck, relevant tests, packaged IPC/native host and offscreen screenshots passed. If the user explicitly requests best-effort installation despite documented incomplete native acceptance, preserve the real profile, verify installed artifact hashes and offscreen startup, and retain the unresolved native gate in the report. Never describe that installation as a verified history export.
- Oct 3 Windows source DLL correction removes two expired-date branches (six bytes); SHA-256 is `1536606b1b1b2a0dc9de631a7f45504f5d466de0979e50b3f94548ae124993d0`. FFI init returned 0 and a wrong host still returned -1006. The Oct 3 NSIS build is installed and Flash is built and tested; their native assets/UI checks passed; no release was published.
- Current acceptance receipts live in `docs/v1.2-verification.md`. Existing-account-key export and scan-only coverage are separate gates; never infer complete RAM extraction from a successful account-key export.
