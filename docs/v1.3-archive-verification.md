# V1.3 archive and export verification

> This document retains the earlier foundation receipts and now records the V1.3 archive implementation. See [current implementation status](v1.3-implementation-status.md) for combined acceptance.

## Archive policy implementation — 21 October

`ArchiveLibrary` now creates and verifies portable, account-scoped JSON/media
archives, reads them without a WeChat connection, carries exact source IDs,
bookmarks and evidence URIs, copies/restores with verification, and persists
scheduled/interrupted jobs. Optional inclusive-second date ranges are validated
at the service boundary and recorded in the archive manifest. The UI offers
optional local start/end dates, translated media states, raw content, exact
DB/table/local-ID provenance and a copyable evidence reference.

Verification checks media links against hashed manifest entries, rejects unsafe
relative paths, verifies media outcome counts and original-only policy, and
recomputes each physical source hash from its exact string ID. Session reader
caches invalidate when file metadata changes. Original-only rejects adopted
image paths whose original tier cannot be proven. Archive filenames preserve
raw IDs beyond JavaScript's safe integer range; retries clear prior outcome
state, and disabled media cannot inherit an earlier attachment link.

Focused command:
`npx vitest run electron/services/archive/archiveLibrary.test.ts electron/services/export/core/mediaSourceIdentity.test.ts`
passed **47 tests**: 28 archive tests and 19 media/formatter tests. These run the
actual archive, formatter and media-copy implementation with controlled local
resolver/source fixtures. They cover original/display/thumbnail, missing local
files, injected decrypt failure, unsupported emoji, not-requested media,
original-only exclusions, source-hash disagreement, path traversal/unlisted
media, corrupted bytes, stale cached evidence, malformed date ranges, portable
bookmarks, cancellation/retry, verified relocation aliases and schedule retention.
They do not count synthetic bytes or injected decrypt failures as real-account
media decryption evidence.

Opt-in scheduled retention now reclaims files from excess managed snapshots
only after a kept snapshot proves coverage of every old physical message with
the same full message content, every old media byte hash, and all portable
bookmarks/tags. Session metadata must match except a valid `weflow.exportedAt`
and independently reproduced `session.messageCount` / `session.lastTimestamp`
(message-array length and maximum numeric `createTime`, in the formatter's
original seconds). Unknown metadata and invalid summaries remain protected.
An inventory captured at scheduled publication includes generated diagnostics;
legacy snapshots without that inventory, changed files, new user files, unique
history/media/annotations and unsafe paths remain visible with a protection
reason. Manual/imported archives are outside automatic retention.

The index durably records a cleanup journal and an explicit potentially partial
state before the first unlink. Prepare/restart hashes both complete inventories;
each unlink rehashes the exact old file and relevant retained data proof file,
with directory/link/source-data boundary checks. The retained manifest is fully
hashed once to establish an immutable local fingerprint (`dev`, `ino`, size,
nanosecond mtime and ctime); every unlink checks that fingerprint before and
after the data checks. It never refreshes that baseline during a cleanup run.
Full inventory hashes still run at prepare/restart and completion. This avoids
rehashing an O(N)-sized manifest for each of N media files. There is no recursive
archive deletion. Only empty subdirectories are removed, and an empty archive
root remains as a crash-recovery anchor. Cancellation/restart resumes the journal;
changed retained dependencies or a different active account stop cleanup. Partial
old snapshots cannot be opened as complete archives. Final checks detect later
changes, but an external edit after an already verified unlink cannot be undone;
the service retains its partial state instead of claiming completion. These
checks rely on local filesystem identity/change timestamps; they are not an
exclusive filesystem lock. Coarse or falsified timestamps and mutations in the
interval between a check and unlink are outside that concurrency guarantee.
Archives should remain unchanged by external tools while cleanup runs.

Focused archive unit verification now passes **51 tests**, including unchanged
and growing formatter-shaped snapshots reclaiming actual disk files, protected
old edits/deletions/media/bookmarks/tags/user files, root/internal links, source
overlap, wrong managed names, invalid summary counters/timestamps, generated
diagnostics, late-added files, dependency changes, cancellation and guarded
restart. A 1 MiB retained manifest is streamed exactly six times across the
entire successful run with both 4 and 96 media files; rewriting its bytes and
restoring the original bytes/mtime still fails closed on its changed ctime.
These fixture tests are not a real-account retention receipt.
Persisted entry/job/schedule paths and pending journal destinations follow
verified storage relocation aliases on startup.

## Reproducible harness

`node scripts/verify-v13-archive-real.mjs` uses `release/win-unpacked/Weport.exe`.
An explicit `WEPORT_ARCHIVE_EXECUTABLE` may select another packaged executable.
The receipt records its SHA-256. The harness copies DB/WAL files to a disposable
account directory, verifies each copy hash and stable source metadata, then uses
a separate profile with a copied Chromium `Local State` for protected settings.
It sets `WEPORT_PROBE_OFFSCREEN=1`, disables notification/network servers and
autostart in that private configuration, and removes the private profile,
snapshot and exported message content when done. It compares the real profile's
config and `Local State` hashes and reports ordinary live-source advancement
separately. It never exports to the user's normal export directory.

Sanitized receipts are `.ui-probe/v13-archive-acceptance/real-export.json` and
`progress.json`. They contain counts, status and executable hashes, not account
IDs, keys, message bodies, media or original paths. A generic failed assertion
includes only the script location; investigate locally without printing data.

## Media identity defect found during fresh-package sampling

The first fresh-package run (ASAR
`9a0835066238a5c3064153caec7d0316271b523e020ee9204fd821cbc1913312`)
passed the full 124,708-message JSON physical-identity audit, then failed the
image-only export identity gate after successfully decoding a real image by
its exact reader identity. The image-only fast media stream did not carry
physical DB/table provenance. The harness stopped at that assertion, deleted
all private data and verified the real profile hashes unchanged. This failure
does not invalidate the full JSON export identity comparison, which uses a
different collection path.

`ExportContext.collectMessages` now accepts a fast media batch only when every
row has a valid exact physical source identity; otherwise it discards that
entire batch and uses the existing canonical cursor. No identity is inferred
from server IDs. `mediaSourceIdentity.test.ts` has three passing regressions for
unscoped, partly scoped and scoped-but-unsafe-number stream rows. The fallback
preserves distinct shard rows with identical local/server IDs and raw IDs beyond
JavaScript's safe integer range. The final rebuilt package passed the same real
image-only identity assertion for all three decoded samples. The sampling
harness records every classification before failing its final integrity gate
if an identity or byte-integrity defect remains.

## Historical foundation limits

The foundation run above predates the implemented versioned account-scoped
portable archive manifest, offline reader/import adapter, portable bookmarks and
evidence references, scheduled jobs and retention. Those features were not
established by that earlier export machinery receipt. The
existing export ledger/manifest is a resumability/integrity artifact, not proof
of that archive-library contract.

The planned explicit media outcomes (original, thumbnail fallback, missing
locally, decryption failure, unsupported) and original-only/best-available policy
are not accepted merely because current code has image tiers or failure counts.
The final run copies databases plus six bounded encrypted image files; it does
not claim complete available-media export, all codec/key combinations, recovery
of absent originals, or a WeChat-independent archive reader. Voice/video/file
real export was not exhaustively verified. No real account is destructively
modified for an injected crash, hang or source-content mutation.
