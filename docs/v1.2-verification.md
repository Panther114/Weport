## Release gates and limits

- Windows no-login RAM extraction, scan-backed mirror connections and the method chooser are excluded from V1.2 and deferred to [V1.3](v1.3-plan.md). Their prior scan coverage (fresh 0/7, stored 6/7) is not a claim about the released existing/manual-key and login-capture path. Scanner controls and production entrypoints are disabled.
- Native macOS arm64 and Linux x64 package/bootstrap/UI acceptance now runs on hosted native runners. Real WeChat key acquisition and real-DB export on those systems remain unverified. macOS ad-hoc signing passes bundle integrity checks; ordinary Gatekeeper acceptance and notarization remain unverified.
- Live notification glass and long-duration real-account stability require further acceptance.
- Linux copied-host reuse checks executable size and mtime; a same-size, same-mtime replacement can retain stale bytes. macOS packaged verification authenticates code/guards after linkage/signing, not every non-text byte; raw pre-packaging verification pins the full source hash.

Earlier matched V1.1/V1.2 sampling (historical fixture, not accepted as this final comparison) found tray RAM 257 → 232.5 MB, idle CPU near the sampling floor, installer 1.24% smaller and popup creation 354 → 319 ms. Foreground RAM and full synthetic-glass CPU were higher; those earlier measurements do not prove improvement on all four axes for this final candidate.
