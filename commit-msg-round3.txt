fix(harness): make chat titles actually generate, and stop stale builds

Two bugs found by verifying instead of assuming.

1. Chat titles never generated. `generateAITitle` sent its request through the
   raw profile while the main chat path goes through `withGatewayHeaders()`.
   OpenCode-family gateways require `x-opencode-session` and answer 400
   ("Request is missing x-opencode-session") without it, so every title request
   failed, the catch swallowed it, and the list kept showing the fallback
   truncation -- which is exactly the reported symptom. Also raised the timeout
   from 15s to 45s: `deepseek-v4.1-flash` spends ~395 of 399 completion tokens
   on reasoning for a 4-character title, so the request was aborted before any
   visible content arrived. Verified on the installed build: fallback
   `分析一下上周群聊` (v1) -> AI `群聊活跃时段分析` (v2) in ~3s.

   `generateAITitle` now accepts an echo of the user's own message rather than
   discarding it (a full sentence beats a truncated fragment), and traces its
   outcome to debug.log under WEPORT_TITLE_PROBE=1 -- the silent
   `catch { return null }` is what made this take so long to find.

2. Stale builds. A leftover batch of tsc-emitted `.js` files sat next to their
   `.ts` sources in `electron/`; Vite resolves `./services/x` to `x.js` first,
   so the main process kept being built from stale code. Every main-process
   change appeared to have no effect, with no error anywhere.
   `scripts/sync-renderer.mjs` now deletes those shadow files before building.

Also fixes the price readout: the panel read `activeModelMeta.cost`, but
`ProviderProfileSummary` never carried a `cost` field, so a priced model
displayed as 未定价. It now reads `modelCosts[model]`, the table the main
process actually resolves from models.dev.
